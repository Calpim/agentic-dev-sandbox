# Gherkin スタイル規約

1. **言語設定**: 必ず先頭に `# language: ja` を宣言すること。
2. **宣言的記述**:
   - UI の操作手順（「ボタンをクリックする」「入力欄にXXを入力する」）ではなく、ドメインの振る舞い・意図を記述する。
   - 良い例: `もし 別の会員がニックネームを "Taro" に変更しようとする`
   - 悪い例: `もし ニックネーム入力フォームに "Taro" とキー入力して送信ボタンを押す`
3. **ルール単位の構造化**:
   - `ルール: [ルール名]` を使用し、ルール直上に `@BIZ-xxx` をタグ付けする。
   - 網羅的なパラメータテストには `シナリオアウトライン` と `例:` 表を活用する。
4. **階層別のタグ付与**:
   - App層 / BFF層のシナリオには、必ず対応するビジネスIDを示す `@covers:BIZ-xxx` を付与すること。
