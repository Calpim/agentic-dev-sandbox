# Pull Request 採点ルーブリック (100点満点 / 85点合格)

本ルーブリックは、プルリクエストおよびコード差分を定量的かつ客観的に評価し、実用性・保守性・安全性を保証するための基準です。

---

## 1. 配点と評価観点

| 評価観点 | 配点 | 評価ポイント |
| :--- | :---: | :--- |
| **アーキテクチャ・設計思想** | **30点** | 責務の明確さ、モジュール分割、DDD/BDD/TDD原則の準拠、スキーマ・契約設計、拡張性 |
| **実装の完全性・動作信頼性** | **30点** | ロジックの正確さ、無限ループやデッドロックの不在、非同期処理（イベントループブロッキングの回避）、状態整合性 |
| **堅牢性・安全性** | **20点** | 入力検証、セキュリティ保護、エラーハンドリング・フォールバック、環境差異（OS・文字コード・ネットワーク障害）耐性 |
| **ドキュメント・コード品質** | **20点** | コメント・docstring、README / 仕様書との整合性、依存関係（requirements.txt等）の明示、設定値の外部化、コード衛生 |

---

## 2. 減点基準ガイドライン

### 【アーキテクチャ・設計思想】 (30点満点)
- **-5〜-10点**: アーキテクチャ原則（例: レイヤード違反、プロンプトとガードの責務混同、ロールとモデルの未分離）に重大な違反がある。
- **-3〜-5点**: 拡張性が低く、設定やモデル名、重要パラメータがコード中にハードコードされている。
- **-1〜-3点**: 軽微な責務の重複や、命名規則・インターフェース定義の曖昧さがある。

### 【実装の完全性・動作信頼性】 (30点満点)
- **-10〜-15点 (致命的)**: 無限ループ、デッドロック、データの不整合、重大なロジック不備が存在する。
- **-5〜-10点**: 非同期（`async def`）環境下での同期I/Oブロッキング（イベントループ停止）、並行処理におけるレースコンディション。
- **-3〜-5点**: LLM出力のMarkdown記法サニタイズ漏れ、境界値・エッジケースの考慮不足。
- **-1〜-3点**: 不要なコード行、未使用変数の残骸。

### 【堅牢性・安全性】 (20点満点)
- **-8〜-15点 (致命的)**: 権限分離や保護ガードの完全バイパス、認証情報の漏洩リスク。
- **-3〜-5点**: コンテナ間の起動順序競合（ヘルスチェック欠如）、Windows CP932 / Linux 環境での文字コードエラー（UnicodeEncodeError）。
- **-1〜-3点**: エラーログの型や詳細情報の欠落、例外の握りつぶし。

### 【ドキュメント・コード品質】 (20点満点)
- **-5〜-10点**: 直接利用しているライブラリが `requirements.txt` / `package.json` に未記載。
- **-3〜-5点**: ローカル開発環境の絶対パス（`D:\...`）のハードコード、README の手順と実装コードの不一致。
- **-1〜-3点**: `.env.example` の記載不足、誤字・脱字、タイポ。

---

## 3. 合否判定ライン

- **85点以上**: ✅ **合格（APPROVED）**  
  実運用に耐えうる品質を満たしている。軽微な改善点（中・低優先度）を指摘した上でマージを推奨。
- **85点未満**: ❌ **不合格（CHANGES REQUESTED）**  
  ブロッキング課題（高優先度）が存在するため修正が必要。優先度順の指摘と、合格ライン（85点以上）に到達するための修正ロードマップを提示する。
